# Безопасный выпуск существующего ai-course-progress — Workers Free

**Только существующий Worker** `ai-course-progress`, база D1 `ai-course-progress` и GitHub Pages. Не создавайте новый Worker, базу или платную подписку.

## Готовность на момент добавления сценария

Подтверждён план **Workers Free** на скриншоте владельца в Cloudflare (18.11.2026); это не означает, что удалённый Worker уже обновлён. В `main` подготовлен API обратной связи, но реальные испытания модели и миграция `0003` пока не подтверждены. Поэтому новый выпуск **всегда оставляет `AI_REVIEW_ENABLED=false`, `AI_REVIEW_CALIBRATED=false` и `AI_REVIEW_FREE_PLAN_CONFIRMED=false`**. Привязка Workers AI сама по себе не вызывает модель; бесплатный дневной расход равен нулю до отдельного проверенного включения.

## Однократная настройка GitHub

В настройках репозитория GitHub → Settings → Secrets and variables → Actions добавить **только** три repository secrets (не вставлять значения в коммиты, сообщения, Issues или логи):

- `CLOUDFLARE_API_TOKEN`: ограниченный Cloudflare API token для конкретного существующего аккаунта, со scope Workers Scripts edit и D1 read/list. Не использовать global API key. Для только inspect достаточен минимальный доступ.
- `CLOUDFLARE_ACCOUNT_ID`: идентификатор существующего Cloudflare аккаунта.
- `CLOUDFLARE_D1_DATABASE_ID`: идентификатор **существующей** базы `ai-course-progress`, не создавать новый ID.

GitHub Actions → **Existing Cloudflare Worker — free-only release** → Run workflow (ветка main). Выбрать `inspect` для тестов, проверки сборки и просмотра ожидающих D1-миграций **без записи**. `deploy-disabled-ai` — отдельное явное действие владельца, которое обновляет Worker с оставленным выключенным ИИ. Не включать этот режим, если удалённая конфигурация отличается от ожидаемой или если `inspect` не прошёл успешно.

Встроенные проверки запускают Node-тесты, Chromium-тесты и сухую сборку Worker. При ошибке — остановка. Версия Telegram-бота и секрет `TELEGRAM_BOT_TOKEN` не переписываются; `keep_vars=true` оставляет настройки панели и секреты. GitHub API token не выводится в лог.

## Что этот выпуск НЕ делает

- Не применяет миграцию D1 `0003_ai_review_budget.sql` и **не меняет пользовательские записи**. Прежде чем запускать удалённые миграции, проверить схему и создать **сохраняемую приватную резервную копию** существующей базы.
- Не вызывает Workers AI, не тратит Neurons, не устанавливает `AI_REVIEW_CALIBRATED=true`.
- Не гарантирует браузерный Telegram OIDC-вход: для него необходима отдельная подтверждённая конфигурация `TELEGRAM_CLIENT_ID`.
- Не включает платный тариф и не повышает лимиты.

Для фактического включения проверки заданий нужен отдельный этап: резервная копия → миграция 0003 → реальная калибровка 20 случаев в рамках Free → контроль качества и приватности → явная активация только при успехе. Результаты офлайновых тестов **не** считаются подтверждением качества реальной модели.

## Диагностика удалённого доступа: Worker отдельно от D1

Первый запуск `inspect` 19.11.2026 остановился из-за неполной истории Git в GitHub Actions. Это исправлено в PR №44. Повторный запуск [#44611448919](https://github.com/antonschtrading-prog/ai-bez-golovnoy-boli/actions/runs/44611448919) успешно выполнил 185 Node-тестов, Chromium, подготовку конфига и `wrangler deploy --dry-run`, но запрос `wrangler d1 migrations list ai-course-progress --remote` получил **Cloudflare 7500: no permission for D1 query**. Это *не* свидетельство повреждения базы или отсутствия миграций и *не* подтверждение подключения работающего Worker.

Исправленный `inspect` отдельно выполняет удалённое чтение списка развёртываний **существующего** Worker и попытку чтения миграций D1. В GitHub Actions → выбранный запуск → **Summary** будут два независимых статуса `CONFIRMED (read-only)` либо `UNVERIFIED / BLOCKED`. При любом неподтверждённом ресурсе запуск остаётся красным и **не разрешает развёртывание**, даже если локальные тесты зелёные. В inspect режиме нет записи, платных вызовов и новых ресурсов.

**Если D1 снова сообщает ошибку 7500:** это недостаточность прав токена для удалённых SQL-запросов Wrangler. Не подменяйте тест миграций другим выводом и не объявляйте базу проверенной. Для выполнения такого запроса обычно требуется разрешение уровня D1 Edit (операции SQL), даже если выполняемый SQL — только чтение. Предоставлять такое право следует лишь после отдельного согласования владельца; оно шире безопасного D1 Read. Можно временно продолжать локальную разработку без живого деплоя.

Ни один из существующих трёх GitHub Secrets менять для этого диагностического сценария не требуется. Не создавать второй Worker, D1 или другой Cloudflare-аккаунт.

# Подключение бесплатной облачной синхронизации — контрольный список

**Статус на 10.11.2026:** серверный код Cloudflare Workers + D1 и тестовые сценарии двух устройств подготовлены, но **реальный Worker, D1, Telegram и вход на сайте не подключены**. Страница `account.html` пока только показывает безопасное сравнение копий, не выполняет вход и не синхронизирует прогресс. **Не обещать пользователю автоматическую синхронизацию до сквозной проверки на iPhone и Mac.**

## Что можно проверить заранее, без реальных аккаунтов

1. Ветка `main`: `npm ci && npm test`.
2. Мобильная проверка: `npx playwright install --with-deps chromium && npm run test:browser`.
3. В тестах D1 применяется **сначала** `0001_schema.sql`, **затем** `0002_oidc_challenges.sql`. Вторая миграция необходима для одноразового входа через браузер.
4. Тест `tests/cloudflare.test.cjs` использует искусственно подписанные RSA/JWT и Telegram initData, проверяет общий аккаунт Mini App + браузер, изоляцию пользователей, одноразовые nonce, ревизии и конфликты. Реальных секретов нет.

## Когда владелец проекта будет дома: реальные подключения

1. Войти в свой Cloudflare и создать Workers + D1 на подходящем бесплатном тарифе (актуальные лимиты проверить в интерфейсе перед созданием). Не вставлять никакие секреты в GitHub или переписку.
2. В локальной рабочей копии создать `wrangler.toml` по образцу `cloudflare/wrangler.example.toml`. Скопировать **фактически выданный Cloudflare** идентификатор D1 в поле `database_id`. Не публиковать в репозитории неутверждённую конфигурацию.
3. Выполнить `npx wrangler d1 migrations apply ai-course-progress --remote` после создания базы. Убедиться, что обе миграции применены, включая таблицу `oidc_challenges`.
4. Настроить собственного Telegram-бота и браузерный вход Telegram у провайдера; домены и redirect URI должны совпадать с фактическими, а не с примерами. Секрет бота задавать **только** через секреты Cloudflare (например, `npx wrangler secret put TELEGRAM_BOT_TOKEN`), а не в файле или в `[vars]`. Публичный Telegram client ID задаётся отдельно как `TELEGRAM_CLIENT_ID`.
5. Развернуть Worker только после проверки переменных окружения, CORS `COURSE_ORIGINS`, D1 binding и HTTPS URL. Провести тесты `/v1/auth/telegram`, `/v1/auth/browser/challenge`, `/v1/auth/browser`, `/v1/session`, `/v1/progress`, не отправляя реальные токены в чат.
6. **Отдельная незавершённая разработка:** привязать интерфейс `account.html` к действующему Worker. Нужны пользовательская кнопка входа, безопасное хранение сессии, выход, предварительное сравнение, явное подтверждение переноса и обработка конфликтов; текущий сайт этих действий ещё не делает. Не запускать автоматическую загрузку локальных данных при входе.
7. После подключения провести сквозную проверку iPhone ↔ Mac: создать черновик на iPhone, синхронизировать, открыть на Mac, отредактировать, проверить конфликт двух одновременных изменений, повторную отправку и выход с устройств. Перед первым переносом скачать резервную копию с каждого устройства.
8. В случае сбоя **не удалять localStorage и не заменять данные**. Сначала сохранить обе версии и диагностировать источник расхождения.

## Критерии готовности

- Один подтверждённый аккаунт Telegram работает с iPhone и Mac, посторонний пользователь не может прочитать данные.
- Черновик и история сохраняются после перезапуска браузера.
- При конфликте ревизий новая версия не затирает старую без явного решения.
- Повторный запрос с тем же idempotency key не создаёт дубликат.
- Пользователь может экспортировать данные до включения синхронизации и после неё.
- Кнопки сайта действительно выполняют синхронизацию; текст «облако включено» появляется **только после проверки**.

**Границы:** GitHub Pages и подготовленный API сейчас не обеспечивают облачную синхронизацию без развёртывания, настройки авторизации и клиентской интеграции. Для работы локальных уроков Cloudflare и Telegram не нужны.

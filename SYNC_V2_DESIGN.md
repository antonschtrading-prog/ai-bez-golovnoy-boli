# Модель синхронизации v2: версионирование, события и миграция

Дата: 10 ноября 2026 года.

## Что добавлено

- `progress-sync-model.js` — чистая модель данных без сетевых запросов и записи в браузер.
- `data-center.html` — кнопка предварительной проверки перехода существующего прогресса в v2.
- Прежние ключи `ai-no-headache-v1` и `ai-course-*-v1` оставлены без изменений.

### Формат снимка

```json
{
  "format": "ai-course-sync-envelope-v2",
  "schemaVersion": 2,
  "deviceId": "browser-preview",
  "revision": 0,
  "serverRevision": null,
  "sections": {},
  "events": [],
  "createdAt": "ISO-8601"
}
```

Снимок `sections` содержит разделы в прежних форматах. Экспорт старой резервной копии может быть преобразован в **новый объект в памяти**, но сам файл и существующие сохранения не перезаписываются.

### Формат события

```json
{
  "id": "device:1:lesson",
  "deviceId": "device",
  "seq": 1,
  "section": "ai-no-headache-v1",
  "kind": "section.replace",
  "at": "2026-11-10T12:00:00Z",
  "baseRevision": 0,
  "value": {"completed": ["a1-1"]}
}
```

При вызове `append` проверяются:
- уникальность идентификатора события;
- порядок последовательности;
- принадлежность событию того же устройства;
- ревизия, на основе которой создано изменение;
- формат и тип раздела;
- допустимость вложенных ключей и ограничение глубины структуры.

Ошибочные и повторные события отклоняются. Вызов возвращает **новый объект**, а исходные данные остаются нетронутыми.

## Принципы разрешения конфликтов

`compare` сравнивает идентификаторы событий и снимки разделов. Различия не разрешаются автоматически. Важно: разный порядок полей JSON в текущей версии может потребовать ручной проверки — сравнительная процедура намеренно консервативна.

Для настоящей синхронизации нужен отдельный серверный протокол: авторизация, проверка принадлежности данных пользователю, серверное назначение ревизий, идемпотентность операций, журнал аудита и защита от повторов. Клиентским `at` и `baseRevision` нельзя доверять как подтверждённым серверным значениям.

**Ограничение:** текущий журнал — экспериментальный формат. Система не записывает события автоматически при выполнении уроков; `section.replace` хранит целый снимок раздела, поэтому перед производственным запуском понадобится ограничить размер и срок хранения журнала, обеспечить миграции и определить правила обновления на уровне отдельных учебных записей.

## Проверено программно без браузера

- Создание и повторное чтение снимка v2.
- Перенос двух разделов из старого формата без изменения оригинала.
- Добавление события повышает ревизию и сохраняет снимок источника.
- Повтор события отклоняется.
- Конфликтующие состояния обнаруживаются.
- Отрицательная ревизия отклоняется.
- Неизвестный раздел отклоняется.
- Опасное имя поля в JSON отклоняется.
- Синтаксис всех изменённых JS/HTML-файлов проверен.

## Не завершено

- Испытания в реальном мобильном/настольном браузере.
- Реальная авторизация и серверная база.
- Сквозная синхронизация между устройствами.
- Автоматическое ведение журнала при действиях ученика.
- Облачный конфликтный протокол и перенос неполных уроков.

До выполнения этих пунктов модуль является **проектным фундаментом**, а не работающей облачной синхронизацией.

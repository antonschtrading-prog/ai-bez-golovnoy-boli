# Правила объединения учебного прогресса — проект 1

Дата: 10 ноября 2026 года.

## Назначение
Определить безопасный порядок объединения двух независимых локальных копий данных до появления сервера и настоящей синхронизации. Реализация: `progress-merge-rules.js`, предварительный просмотр: `data-center.html`.

**Ни один файл не объединяется и не перезаписывается автоматически.** Предварительный план — анализ, а не разрешение на перенос.

## Политика по типам данных

| Данные | Правило |
|---|---|
| Завершённые уроки (`completed`, `deepDone`, `extendedDone`) | Объединить уникальные стабильные идентификаторы, если оба значения — корректные списки |
| Независимые ответы / записи с различающимися ключами | Сохранить обе записи в черновике, не изменяя источники |
| Два черновика с одним идентификатором и разным содержимым | Конфликт; сохранить оба, решение пользователя |
| Два результата одного экзамена с разным содержимым | Конфликт; нельзя выбирать более высокий результат или более позднее локальное время наугад |
| История повторений и попыток с одинаковым ключом | Конфликт; нельзя просто сложить счётчики или заменить запись |
| Выбор ИИ, текущее занятие, настройки, прочие поля | При различии — конфликт до появления утверждённого правила |
| Раздел отсутствует в одной из копий | Существующую запись можно сохранить без реконструкции пропущенных данных |
| Некорректные структуры или неизвестные имена | Не считать безопасным объединением |

## Почему не «более свежая запись»
Локальное время устройств может отличаться; поздняя запись может оказаться более старым содержимым. Для будущей облачной версии потребуются серверные ревизии, идентификаторы операций и отдельная обработка конфликтов.

## Испытанные сценарии
- Объединение двух списков завершённых уроков — допускается.
- Два разных черновика одной работы — конфликт.
- Два различных экзамена одного уровня — конфликт.
- Независимые практические работы — черновик объединения без конфликтов.
- Разные счётчики повторений одной темы — конфликт.
- Разный выбор ИИ — конфликт.
- Недопустимое имя записи в JSON — отклонено.
- Проверена неизменность входных объектов во время построения плана.

## Что необходимо до автоматического переноса
1. Стабильные идентификаторы событий и версий записей.
2. Копирование исходных данных и журнал миграции.
3. Серверные права доступа и проверка принадлежности записей пользователю.
4. Разрешение конфликтов без потери версий.
5. Сквозные испытания экспорта, восстановления, перезагрузки и работы на нескольких устройствах.

Данные инструменты сейчас работают только в локальном браузере. Они не являются облачной синхронизацией.

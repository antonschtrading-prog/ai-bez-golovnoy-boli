# Проверяемая повторная отправка офлайн-операций

В проекте уже есть `progress-outbox.js`; новую очередь создавать не требуется. Добавлен дополнительный метод `flushVerified(client)`, не изменяющий существующий контракт `flush`.

- Только после явного подтверждения учеником вызвать `enqueue(sections,revision)`; тогда сохраняется одна операция на подтверждённый аккаунт.
- `flushVerified` вызывается **вручную**. Перед отправкой он читает сервер, не отправляет устаревшую ревизию и использует исходный `Idempotency-Key`.
- После попытки записи снова читает сервер; удаляет ожидающую операцию только если серверная ревизия выросла и содержимое совпало.
- Если ответ был потерян после записи, следующий запуск узнаёт сохранённые данные и не повторяет отправку.
- Если серверная версия конфликтует, pending остаётся; пользователь должен отдельно решить конфликт. Ошибка сети не удаляет накопленную работу.

**До включения в аккаунте:** Web Locks / IndexedDB против одновременных вкладок, явный экран очереди и резервного экспорта, привязка к проверенному аккаунту после повторного входа, сквозной тест iPhone ↔ Mac. Автоматическое возобновление не включать. Старый `flush()` оставлен ради совместимости и не следует использовать для новых сценариев с повышенными требованиями к подтверждению доставки.

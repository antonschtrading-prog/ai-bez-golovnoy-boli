# Устойчивая ручная очередь синхронизации

Модуль `progress-durable-outbox.js` — изолированный механизм, **пока не подключённый к сайту**. Ни авторизация, ни сохранение уроков автоматически его не вызывают.

## Порядок
1. Только в авторизованном аккаунте создать `CourseDurableOutbox.create({storage,progressStorage,client,accountId,uuid})`. `storage` должен быть долговременным хранилищем, а `uuid` — криптографически стойким генератором UUID; `client` — привязанным к подтверждённому аккаунту.
2. По действию пользователя вызвать `prepare()`: получить свежую облачную версию и сравнить с локальной. Конфликт блокирует запись.
3. Показать пользователю предложение и отдельное подтверждение. По его действию вызвать `approve(ticket,true)` — **сначала сохранится** единственная операция в локальном outbox. В облаке пока ничего не изменится. Ошибка записи в локальное хранилище блокирует отправку.
4. Только по отдельному действию вызвать `sendPending()`. Модуль перечитывает облако, не отправляет устаревшую ревизию, использует те же `Idempotency-Key` и полезную нагрузку при повторах. После ответа заново проверяет облако и лишь затем удаляет запись. При недоступной сети операция остаётся.
5. После перезапуска — заново авторизоваться в **том же** аккаунте, проверить `pending()`, предложить явно продолжить или вручную разрешить конфликт. Никакой отправки при загрузке страницы.

## Обязательные ограничения перед боевым включением
- Код **не** обеспечивает атомарность между вкладками (localStorage не предоставляет CAS). Перед реальной интеграцией добавить Web Locks или IndexedDB-транзакции; запрещать одновременное управление очередью из нескольких вкладок.
- Очередь содержит открытые тексты работ: нужно оценить угрозу XSS, объём данных, очистку при смене пользователя и сценарии отказа браузерного хранилища. Нельзя хранить там токен авторизации.
- Не заменять основной локальный прогресс. Нельзя считать доставку успешной только по HTTP 200 — обязательна повторная проверка.
- Одна операция на аккаунт; при конфликте нельзя заменять её новой. Нужен пользовательский интерфейс для резервного экспорта, разрешения конфликта и безопасного удаления подтверждённой/отменённой операции.
- Не путать серверное сохранение с полной двусторонней синхронизацией: для реального продолжения на другом устройстве необходимо безопасное применение облачной копии к локальному курсу с предварительной резервной копией и явным согласием.

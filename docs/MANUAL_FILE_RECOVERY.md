# Ручное восстановление из скачанной резервной копии

После входа в тот же подтверждённый Telegram-аккаунт пользователь выбирает ранее сохранённый JSON из раздела «Резервные копии», нажимает «Проверить выбранный файл», затем отдельно подтверждает восстановление. **Никакой отправки файла в интернет нет.**

Проверка:
- Формат `ai-course-cloud-restore-backup-v1`, все семь исходных ключей, ревизия, дата и точный Telegram account ID.
- У каждого раздела должна быть корректная схема; потенциально опасные вложенные имена отвергаются.
- Сравнение проводится с текущей локальной версией. Разные записи одной работы блокируют перенос.
- Перед записью сохраняется и перечитывается отдельная резервная копия **текущих** локальных данных, затем каждый изменяемый раздел проходит через существующую историю версий `CourseStorage.write`.
- При сбое делается условный откат только тех записей, которые программа сама успела изменить. При неполном откате программа сообщает об опасном состоянии и оставляет резервную копию.

Требования и ограничения: доступ к Telegram нужен, чтобы исключить импорт файла чужого аккаунта; при полном отсутствии сети для нового входа импорт заблокирован. Отложенные отправки в облако предварительно должны быть разрешены. Между вкладками аккаунта применяется Web Lock, но страницы уроков пока не используют общий lock и их следует закрыть при импорте. Это не замена пользовательскому тесту Safari/Chrome и не фоновая синхронизация.

# Ручная очередь на странице аккаунта

Раздел «Офлайн-очередь» использует существующие `progress-outbox.js` и `flushVerified`. Новые файлы: `account-outbox-controller.js`, `account-queue-page.js`.

**Без автоматической синхронизации:** вход лишь определяет аккаунт; сохранение операции и отправка — разные явные действия. Сначала «Проверить и подготовить очередь», затем подтверждение сохранения локальной операции; при наличии интернета — отдельная кнопка «Проверить и отправить ожидающее».

Защитные границы:
- Очередь привязана к подтверждённому Telegram account ID; токены туда не попадают.
- `navigator.locks` сериализует работу нескольких вкладок одного браузерного origin; если Web Locks отсутствует, очередь недоступна (fail closed).
- Подтверждение повторно сверяет актуальные локальные и удалённые данные перед сохранением.
- При обрыве сети и неизвестном результате очередь остаётся; повторно используется тот же ID операции. Удаление ожидающей операции — только после проверки облака.
- Прямое сохранение на странице блокируется, если существует ожидающая операция.
- Экспорт очереди создаёт JSON с учебными ответами: хранить его как конфиденциальный файл. Повреждённая очередь не удаляется автоматически.
- Облачные данные **не записываются обратно в локальные разделы**. Для полноценной двусторонней синхронизации требуется отдельный безопасный импорт с резервной копией, блокировками и тестами iPhone/Mac.

Ограничения: `localStorage` не защищён от удаления пользователем, очистки Safari/браузера, нехватки квоты или XSS. Блокировки действуют только среди вкладок одного origin, а не между разными устройствами. Настоящие Telegram/Cloudflare подключения ещё требуют настроек и сквозных тестов. Никакой silent retry и автоматической фоновой отправки нет.

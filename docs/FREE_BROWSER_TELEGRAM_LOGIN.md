# Бесплатный единый вход: браузер + Telegram Mini App

Состояние: подготовка в отдельной ветке, без публичного запуска и без платных внешних сервисов.

## Почему два пути ведут в один аккаунт

- Mini App: существующий `POST /v1/auth/telegram` проверяет HMAC `initData` и читает Telegram `user.id`.
- Браузер: новый OIDC `id_token` проверяется по публичным ключам Telegram `https://oauth.telegram.org/.well-known/jwks.json`, с проверкой RS256, `iss`, `aud`, времени, серверного `nonce` и **подписанного поля `id` из профиля**.
- OIDC `sub` не предполагается равным Telegram `user.id`; оба входа используют только подтверждённый Telegram ID в одной таблице `telegram(user,account)`.
- Если в подписанном OIDC-токене нет целочисленного `id` (профиль), объединять аккаунты запрещено.
- Подпись JWT проверяет сервер. Клиентский `user` из Telegram SDK никогда не используется для установления личности.

## Защита от повторов

`POST /v1/auth/browser/challenge` создаёт криптографически случайный nonce, действительный 5 минут и записанный в D1. Затем Telegram Login SDK включает nonce в ID Token. `POST /v1/auth/browser` проверяет JWT и **атомарно удаляет nonce**; повторное предъявление старого ответа не выдаст новую сессию.

Оба публичных метода требуют разрешённого `Origin`; CORS не принимает посторонние сайты. Никаких Bearer-токенов в URL. Токены аккаунта создаются только после успешной проверки личности. Сеансы можно отозвать существующим `DELETE /v1/session`.

## Браузерный адаптер

`browser-telegram-login.js` — независимый модуль, который вызывается только после явного клика пользователя:
1. До показа активной кнопки вызывает асинхронный `prepare()` и получает nonce от API (5 минут действия).
2. **Непосредственно в обработчике клика, без промежуточных await**, вызывает `login()`, который синхронно открывает `Telegram.Login.auth({client_id,scope:['profile'],nonce},callback)`. Это важно для Safari и блокировки popup.
3. Передаёт только `id_token` и nonce на сервер и получает свою локальную сессию.
4. Держит серверный токен **только в оперативной памяти** JS; выход пытается отозвать токен и всегда очищает локальное состояние. Для повторного входа потребуется снова выполнить `prepare()`.

Чтобы интегрировать его в интерфейс, потребуется разрешённый в @BotFather домен, публичный Client ID, HTTPS Workers и официальный SDK (`https://telegram.org/js/telegram-login.js`). Проверить поведение popup в Safari на iPhone/Telegram WebView отдельно. Открыть popup нужно из пользовательского действия; сетевой запрос за nonce до открытия popup может блокироваться браузером — при интеграции предусмотреть инициирование авторизации по правилам пользовательского жеста, проверить в Safari.

## Бесплатная модель

GitHub Pages + Cloudflare Workers Free + D1 Free, без обязательных платных зависимостей. Нужен Telegram-бот, который создаётся бесплатно, и аккаунт Cloudflare Free. **Никакие реквизиты оплаты и секреты пока не нужны в GitHub.** Если конкретная регистрация потребует карту или оплату, внедрение останавливается и выбирается бесплатная альтернатива.

## До production

- Настроить бота в @BotFather: Allowed URLs, Client ID, секретный Bot Token. Секрет хранить только в Cloudflare secret, не в URL, JS, GitHub или переписке.
- Удостовериться, что Telegram SDK использует обещанный nonce и возвращает подписанный `id` при `scope:['profile']`.
- Подтвердить работу на реальном Telegram, iPhone Safari и Mac; тесты сейчас используют синтетические RSA ключи и подписанные объекты.
- Добавить rate limiting публичных auth endpoints, квоты CPU и D1, резервные копии, автоматическое ограничение размера истории, политику удаления данных, перенос локального прогресса только после явного согласия.
- Нельзя подключать работающий курс к облаку до end-to-end проверок, корректного разрешения конфликтов и подтверждения восстановления черновиков.

# Telegram Mini App: бесплатный вход, подготовка

Этот модуль не создаёт Telegram-бота, не требует платного внешнего провайдера и не выполняет публикацию API. Telegram Mini App использует подписанную Telegram строку `Telegram.WebApp.initData`; клиентский `initDataUnsafe` для подтверждения личности запрещён.

## Как устроен вход

1. Будущий интерфейс Mini App отправляет сырую строку `initData` на `POST /v1/auth/telegram` через HTTPS.
2. Сервер проверяет HMAC-SHA256 по **секретному** токену бота, отсутствие повторных полей, время выдачи (не старше 5 минут, допуск будущего времени 30 секунд), наличие корректного положительного Telegram ID.
3. Повтор того же `initData` отклоняется с `409 replayed_init_data`. Отпечаток хранится в D1, старые записи автоматически удаляются при новых входах.
4. Telegram ID связывается с внутренним случайным идентификатором аккаунта. При последующих входах возвращается **тот же аккаунт**, не новый. Если Telegram ранее был связан с уже существующим аккаунтом, связь сохраняется.
5. Сервер выпускает криптографически случайный Bearer-токен, срок которого ограничен. Токен не попадает в URL.
6. Клиент может использовать существующий `GET /v1/session`, `GET/PUT /v1/progress`, `DELETE /v1/session` после входа.

В Worker секрет читается **только** из `env.TELEGRAM_BOT_TOKEN`, в GitHub токен не хранится. Если токен не задан, вход возвращает 503, а не пытается пропустить проверку.

## Технические ограничения

- Нужен реальный бот Telegram и его секретный токен, полученный владельцем. Токен НЕ должен передаваться в чат или коммит.
- **Это пока вход только из Telegram Mini App**. Обычный браузер Safari/Chrome не получает `Telegram.WebApp.initData`; для него нужно отдельно реализовать подтверждённый Telegram Login или другой бесплатный вход.
- Публичный API не развёрнут, клиентский интерфейс не переключён на облачное хранение.
- До реального запуска нужны лимиты частоты запросов, защита от исчерпания квот бесплатного тарифа, резервное копирование и удаление персональных данных.
- Авторизация не означает автоматическую отправку локального прогресса: перенос по-прежнему требует явного подтверждения и предпросмотра конфликтов.
- Реальные Telegram WebView, устройства и CPU-бюджет Workers Free ещё не проверялись.

Алгоритм подписи проверен по официальной документации: https://core.telegram.org/bots/webapps

## Проверки

`tests/cloudflare.test.cjs` добавлены: корректная подпись и новый аккаунт, повторный вход с тем же accountId, защита от повторного initData, изменения ID, истечения времени, других секретов и отсутствующего токена. Тестовый токен фиктивный и не является секретом.

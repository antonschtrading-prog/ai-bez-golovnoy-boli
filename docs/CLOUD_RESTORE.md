# Безопасное получение облачного прогресса на устройство

Новые модули: `account-cloud-restore.js` и `account-cloud-restore-page.js`. Они используют уже существующие `CourseAccountPreview`, `CourseStorage.write` и `CourseStorage.rollbackBatch`.

## Сценарий

1. Пользователь входит через проверенный Telegram-аккаунт в браузере или Mini App.
2. Нажимает «Проверить облако и локальные данные». Система сверяет все семь разделов. Разные значения одного и того же незавершённого ответа считаются конфликтом — автоматическая замена запрещена.
3. Перед подтверждением система вновь читает сервер и локальные данные под Web Lock. Изменение любого снимка блокирует операцию.
4. Создаётся и проверяется самостоятельная локальная резервная копия всех исходных значений под ключом `ai-course-cloud-restore-backup-v1:<UUID>`. При отказе quota или хранилища основной прогресс не меняется.
5. Каждый изменяемый раздел сохраняется через существующую систему истории версий. При ошибке последующие разделы не пишутся, уже записанные откатываются при условии, что никто не изменил их параллельно.
6. Если откат не полон, пользователь получает точное предупреждение и ссылку на локальный идентификатор резервной копии. Она не удаляется ни после успеха, ни после отказа.
7. После успешного восстановления пользователь открывает курс или незавершённый урок заново; страницы читают привычные локальные ключи.

## Ограничения

- Это ручное восстановление после **явного согласия**, а не фоновая синхронизация в реальном времени. Сетевые запросы при открытии страницы не выполняются.
- Текущий прогресс также может измениться из уже открытой вкладки курса; дополнительное сравнение исходных строк предотвращает часть гонок, но для строгой атомарности между вкладками все writers уроков должны использовать один согласованный Web Lock.
- `localStorage` и сохранённая локальная резервная копия могут быть очищены браузером, а также доступны JavaScript данного origin. Для серьёзного запуска необходимы пользовательская выгрузка резервной копии, тесты на Safari и Chrome, отдельное облачное хранение черновиков и XSS-аудит.
- При несовместимых версиях незавершённых работ пользователь должен разрешить конфликт явно, никакого last-write-wins.
- Реальное подключение Telegram и Cloudflare секретов/доменов не является частью этой ветки.

# Бесплатная инфраструктура — решение для проекта

## Принцип

Не включать платные сервисы, trial, автопродление с платежами или платные надстройки. Начальный план: **GitHub Pages + Cloudflare Workers Free + Cloudflare D1 Free**. Приложение должно корректно отвечать об ошибке при исчерпании квоты: не удалять локальный черновик и не требовать апгрейда для продолжения локальной работы.

Актуальные официальные лимиты, проверенные 10.11.2026:
- Workers Free: 100 000 запросов/сутки, 10 мс CPU на запрос. https://developers.cloudflare.com/workers/platform/limits/
- D1 Free: 5 млн прочитанных строк/сутки, 100 000 записанных строк/сутки, суммарно 5 ГБ хранения; одна БД до 500 МБ. https://developers.cloudflare.com/d1/platform/pricing/ и https://developers.cloudflare.com/d1/platform/limits/
- После исчерпания бесплатной D1-квоты запросы завершаются ошибкой до сброса лимита или освобождения хранилища; автоматическое расширение в платный план **не заложено**. https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/

Оформление бесплатной учётной записи Cloudflare, доступность сервисов и требования к оплате в конкретной стране проверяются **в момент регистрации**. В этом проекте не создавали аккаунт, не привязывали карту и ничего не разворачивали.

## Файлы

- `cloudflare/migrations/0001_schema.sql`: подготовительная структура D1, без удаления прежних данных.
- `cloudflare/d1-store.mjs`: чтение прогресса, история, идемпотентные операции и серверное управление сессиями через D1.
- `cloudflare/api.mjs`: Workers Fetch API с явной авторизацией, CORS, лимитом тела и проверкой ревизий.
- `cloudflare/worker.mjs`: точка входа (без публичной регистрации).
- `cloudflare/wrangler.example.toml`: **образец** конфигурации. Не включать placeholder ID в боевой деплой.
- `tests/cloudflare.test.cjs`: проверки через реалистичную SQLite-модель D1, не через удалённый Cloudflare.

## Граница безопасности

Существующий Node.js API и Worker API раздельны. Оба требуют уже выданный доверенным сервером Bearer-токен. В Worker **нет публичного endpoint** для произвольного создания учётной записи или получения токена. Не подключены Telegram-вход и провайдер подтверждения личности. `issueSession` служит только внутреннему компоненту после проверки личности.

Перед реальным запуском обязательно добавить поставщика входа, ограничение частоты запросов, лимиты места на пользователя, ротацию сессий, безопасное резервирование/восстановление базы, мониторинг бесплатных лимитов и политику удаления. Использовать исключительно Free plan; не предлагать перевод на оплату как нормальное поведение приложения.

## Следующие шаги без участия пользователя

1. Проверить синтаксис/схемы/откат в CI, продолжить тесты конкурентной записи в D1.
2. Реализовать бесплатную авторизацию с подтверждённой личностью, без платной рассылки OTP. Возможный путь: Telegram Mini App и Telegram Login, с серверной криптографической проверкой и привязкой аккаунта; необходим токен бота, который пользователь получит позже.
3. Сделать интерфейс явного переноса локальных работ в аккаунт с предпросмотром конфликтов, и только затем включить автоматическую синхронизацию.
4. Тестировать в локальном Wrangler/D1 и настоящих устройствах; без подтверждения совместимости публичный деплой не делать.

Предупреждение: официальный Workers Free имеет лимит CPU 10 мс на запрос. Реальную производительность криптографической проверки и обработки крупных учебных снимков ещё необходимо измерить в Worker, а не предполагать, что Node.js тесты доказывают работу в этих лимитах.

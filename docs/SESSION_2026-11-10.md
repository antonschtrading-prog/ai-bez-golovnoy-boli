## Исправления по результатам проверок

- Версии, сохранённые в одну миллисекунду, могли сортироваться по случайному UUID. Теперь время снимков монотонно.
- Старый полный экспорт включает диагностический журнал: он исключается из учебных разделов v2, но сохраняется в исходной копии.
- Некорректный старый экспорт без объекта items мог превратиться в пустую миграцию. Теперь отклоняется.
- Добавлены недостающие проверки deepAnswers и notes, вложенных опасных ключей при одностороннем слиянии, предела журнала v2.
- Ошибка базы при проверке сессии могла выйти за обработчик HTTP-ошибок. Теперь возвращается обезличенный 500, а сервер продолжает обслуживать запросы после восстановления базы.
- Конфликт другой вкладки сохраняет предлагаемый текст в отдельной версии вместо молчаливой перезаписи.

## Что осталось и почему это не облачная синхронизация

- Ветка подготовлена в PR; `main` и действующий GitHub Pages не обновлялись.
- Нет подключённого провайдера email/OIDC, публичного сервера и реальных пользовательских сессий. Сервер локальный, не production-ready.
- Клиентский адаптер не подключён к автосохранению. Ещё нужны outbox, разделение анонимного прогресса и аккаунтов, вход/выход, перенос между устройствами и интерфейс серверных конфликтов.
- Telegram-бот/SDK, вход через Telegram и UI привязки не включены; реальный токен не использовался.
- LocalStorage не даёт атомарной транзакции между вкладками. Проверки обнаруживают устаревшие копии и сохраняют кандидатов, но узкая гонка остаётся. Следующий этап — IndexedDB/Web Locks с асинхронными обработчиками. Многоключевой импорт также имеет best-effort rollback.
- История ограничена 20 последними сохранениями, хранит целый раздел, не является долговременным архивом. Её импорт из скачанного файла пока не реализован; текущее восстановление работает из истории данного браузера.
- До сервера нужны квоты, rate limits, защищённые резервные копии, проверка восстановления, отзыв сессий и политика удаления пользовательских данных.
- Реальные старые файлы учеников, Safari/iPhone, Telegram WebView и сквозной обмен между устройствами не проверены.

Платная инфраструктура не подключалась, финансовых операций не было. Production-секреты и конфиденциальные пользовательские данные не использовались.

# Сеансы и сквозная синхронизация: подготовительный блок

Дата: 10 ноября 2026 года.

## Выполнено

1. **Серверные операции сеанса**: `GET /v1/session` подтверждает принадлежность уже аутентифицированного токена конкретному аккаунту; `DELETE /v1/session` отзывает токен через хэш в SQLite.
2. **Клиентский API** `progress-client.js`: методы `session()` и `logout()` поверх защищённого Bearer API, без локального хранения токена внутри клиента.
3. **Координатор** `progress-sync-coordinator.js`: связывает подтверждённую сервером учётную запись с локальной очередью, получает реальную серверную ревизию, рассчитывает план слияния, блокирует неоднозначные конфликты.
4. **Явное согласие**: `queue(sections,{confirmed:true})` обязателен перед постановкой локальных ученических данных в очередь. Вызов `connect()` сам ничего не выгружает.
5. **Выход**: серверная сессия отзывается, внешний колбэк очищает реквизиты устройства; результат отдельно сообщает, подтверждён ли отзыв сервером. Ожидающий черновик остаётся в локальном аккаунтном outbox для последующего восстановления.
6. **Тесты** `tests/session-sync.test.cjs`: реальный HTTP API на временном локальном порту с SQLite; два разных устройства на одном аккаунте, третий изолированный аккаунт; независимые черновики, конфликт офлайн-устройства, выход и отзыв токена, отказ сети, недоверенный идентификатор, обязательное согласие и гонка выхода с чтением.

## Что важно

- **Это не система регистрации пользователей.** `Store.provision()` работает только как закрытый тестовый / административный механизм. Ручной ввод логина/пароля на сайт не добавлен; хранение паролей в браузере или создание собственной ненадёжной системы логина недопустимо. Перед реальным запуском нужно выбрать поставщика входа (OIDC/email) и выполнить *серверную* проверку идентичности с выпуском/отзывом сессий.
- Тесты используют фиктивные, заранее выданные сервером токены, не реальные аккаунты и не реальные записи учащихся.
- Код не выполняет сетевых запросов до явного вызова координатора. Рабочий интерфейс курса продолжает локальное сохранение.
- Отзыв сервера при отсутствии сети не может быть подтверждён. В этом случае пользователь должен получить предупреждение; очистка локальных реквизитов осуществляется отдельно. Серверный токен прекращает действовать после своего срока истечения.
- Очередь пока хранит *полный снимок* в `localStorage`; для устойчивой офлайн-работы с частыми изменениями нужны IndexedDB/outbox по отдельным заданиям, решение конфликтов и интеграция автосохранения.
- `GET /v1/session` возвращает непрозрачный идентификатор аккаунта в ответ на авторизованный запрос; это не способ войти без проверки токена.
- До выпуска публичного сервера необходимы ограничения частоты запросов, квоты, TLS, резервные копии, проверка восстановления, политика удаления и журнал действий.

## Проверки перед объединением

- `npm test` — весь существующий набор тестов и новые HTTP/сеансовые сценарии.
- `npm run test:browser` — регрессия текущего курса и IndexedDB.
- Дополнительно подтвердить отсутствие изменений утверждённых учебных материалов.

Временная ветка `feat/sync-session-orchestrator` предназначена только для ревью. Реальная облачная синхронизация, Telegram-бот и внешний сервис авторизации ещё не включены.

## Доверенная выдача сеансов

`Store.issueSession(accountId, ttlMs)` создаёт криптографически случайный Bearer-токен; в таблице `sessions` сохраняется только его SHA-256, а вызывающему доверенному серверному компоненту возвращаются токен и дата окончания срока. Длительность ограничена 1 минутой — 30 днями, значение по умолчанию 7 дней. `Store.revokeAll(accountId)` отозовёт все сессии аккаунта, например для будущей операции «выйти со всех устройств». Эти операции доступны **только серверному коду**: в HTTP API нет публичного endpoint для самостоятельного выбора accountId и выпуска токена.

Перед реальной интеграцией потребуются верификация OIDC/email identity, привязка внешнего subject к внутреннему accountId, rate limiting, контроль жизни/обновления токена и защита логов от токенов. Сама выдача случайного токена **не является** готовой регистрацией или авторизацией.
